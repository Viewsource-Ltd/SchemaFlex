The short version

  • SchemaFlex the tool sends nothing anywhere. It is a local command-line program. It connects to the database you point it at (optionally through an SSH tunnel you configure with --ssh-host), reads the schema, and writes the HTML file you asked for — that's the entire network and disk footprint.
  • Your connection string and schema never reach us. There is no server component, no telemetry, and no analytics built into the tool itself.
  • This website is a static marketing page. It doesn't run any of your data through anything — the example diagram on the homepage is a fixed file generated ahead of time from a sample database, not a live connection.

The SchemaFlex CLI tool

SchemaFlex is a .NET console application you run on your own machine. When invoked, it opens the database connection you supply, reads table, column, key, index, constraint, trigger and enum metadata, and serializes that into a single HTML file alongside a bundled viewer template. It then exits.

It makes no network request other than the one database connection you give it in --connection (and, if you supply --ssh-host, the SSH tunnel that connection is routed through). It has no update checker, no crash reporter, and no analytics of any kind. The only thing it writes to disk is the output file you asked for (default erd.html).

This website

This site describes SchemaFlex and links to where you can download it. It has no accounts, no forms, no cookies and no client-side scripts of its own beyond a small script that highlights the current section in the navigation bar — every page is plain, static HTML hosted on GitHub Pages.

Like any web server, the infrastructure hosting this site keeps standard access logs (requesting IP address, timestamp, page requested, response status, user-agent) for operating and securing the service. These are not combined with anything SchemaFlex the tool does on your machine, because the two have no connection to each other.
